Divine Videos

Not signed yetKind 39998Shared concept

A decentralized list of the short looping videos posted on Divine (divine.video), including the classic Vines Divine restored. Avi signs this header once. A dedicated curator bot then files one item per video under it, so the list renders on brainstorm.world with a poster, a player and a link back to Divine.

Round 1 feedback

What changed after review

  • Title is the first required field.Renderers with no display hints show the first required field as the item's name, so title leads and video follows. One side effect for Vinney: Brainstorm's "also listed by" matches items on the first required value, so unrelated videos with the same title (a lot of Vines are titled "lol") would show as the same thing. Worth keying that on something else.
  • Links come from URL templates.Two 9999 items in the URL Templates list, pinned by event id: Divine video filled from a new divine-id field, and Divine profile filled from creator-npub. Items no longer carry divine-url, creator-page or vine-url. If Divine changes its URL scheme, one header edit fixes every link.
  • Why divine-id and not sha256.Divine's video page opens native videos by file hash, but a classic Vine only opens by its Vine id: the hash URL returns "Video not found". divine-id is the Divine event's own d tag, which works for both.
  • No vine.co link.vine.co still answers, but with the old Vine app shell, and nothing showed it plays. On a Vine item, divine-id already holds the Vine id.
  • vine-likes is a fact next to vine-loops.
  • List image: the Twemoji clapper board.Same pattern as NosFabrica's copy of Food and Drink Places, an SVG on jsDelivr. Divine's own logo is left out because its brand guidelines grant no third-party use and it would read as Divine endorsing the list. If the Divine team offers a logo later, it is a one-line change and a re-sign. An r tag links the Twemoji licence (CC BY 4.0).
  • The header is replaceable.Only its address is fixed. Renaming a field later means the bot republishes its items, so names are still worth settling now.
  • David's o tag.Display and link hints stay in the header for now, since that is where Brainstorm reads them. If the convention lands they can move to a UI event with ["o", <header address>, "UI"]; field declarations and types are schema and would stay here.
Still open

Questions for the team

  • The p tag.Kept for now. It is the standard nostr link to the creator, and a few nostr apps might show a mention notification.
  • Classic Vines.About 2.22 million. Native videos first (about 51 thousand), then Vines once we know dcosl can hold them. Who confirms capacity?
  • Brainstorm registration.The item page with a player needs the coordinate in dictionary.config.json, with search left off so queries containing "video" don't all match this list.

URL templates

Each template is a kind 9999 item in the URL Templates list (39998:2efaa715…:url-templates), signed by Avi. The header names it by event id, so it can't be edited under this list. Templates follow the list's rules: a literal https host, then {name} placeholders that Brainstorm percent-encodes.

    Identity
    
Linking each video to its creator

    
Divine hides nostr from its users. Most sign in with an email, and Divine's login service creates and holds a key for them. Each video is still signed by that account's own key, so the signer of the Divine event is the creator.

    
    
      
  • The npub is the identity that lasts. Divine is building key export, and its terms treat the keypair as the account. Usernames like alice@divine.video are optional, and Divine's terms say it can revoke or reassign them.
    • 
      
  • Classic Vines are signed by one archive key per original creator, which Divine holds until that creator claims the account. The field descriptions say so.
    • 
      
  • Custody limits what the signature proves. It shows which Divine account posted a video, not which person.
    • 
      
  • On every item: p (creator's pubkey), creator, creator-npub, and creator-nip05 only when it resolves to the same pubkey when the item is built. The profile link is built from the npub, so it survives a username change.
    • 
      
  • Not treated as creators: "inspired by" credits, collaborators, and people who repost.

    Bot rules
    
What the curator bot will and won't list

    
    
      
  • One item per Divine video, kind 39999, filed under this header with one z tag. Re-running the bot updates an item in place.
    • 
      
  • Skipped: videos the creator flagged with a content warning, videos whose event expires, and videos whose file or thumbnail no longer loads.
    • 
      
  • Deleted in turn: when Divine's relay carries a deletion for a video, the bot deletes its item (kind 5).
    • 
      
  • Not copied: the media itself. Items point at Divine's files.
    • 
      
  • Order of work: a 150-item pilot, then the native videos with ongoing sync, then classic Vines once capacity is confirmed.

The header Avi will sign

    
Avi first signs the two URL templates (or reuses them if they are already on the relay). Their event ids replace the @template: placeholders in the two link tags, then the header is signed. The id, pubkey, created_at and sig are added at signing.
